# BUG TRACE

### 컴퓨터는 왜 이런 행동을 할까?

IME 조합 오류, 부동소수점 오차, 문자 인코딩 불일치처럼 컴퓨터에서 발생하는 신기한 오류의 원인과 작동 원리를 분석하는 웹앱입니다.

🔗 웹앱 주소: https://bug-trace2-bqzgnugxyavjctzeovwxxn.streamlit.app/

## 1. 탐구 동기

비트 단위 연산 수업에서 정수를 2의 보수로 저장하는 방법을 배우며, 정해진 칸 수를 넘으면 음수가 되는 오버플로를 알게 되었습니다.
여기서 **"그렇다면 실수는 비트로 어떻게 저장될까?"** 라는 의문이 생겼고, 0.1 + 0.2가 0.3이 아닌 이유(IEEE 754)를 탐구했습니다.
이어서 **"컴퓨터가 모든 것을 숫자로 저장한다면, 글자에도 같은 문제가 생기지 않을까?"** 로 확장해 문자 인코딩과 유니코드를 조사했고,
평소 한글 문서를 쓰며 직접 겪었던 '완선 → 완완성' 현상까지 같은 원리로 추적했습니다.

## 2. 탐구 사례 (탐구 순서)

| 번호 | 사례 | 핵심 원리 |
|---|---|---|
| BUG-001 | 2의 보수 정수 오버플로 | 정해진 비트를 넘으면 가장 작은 음수로 넘어감 (2038년 문제) |
| BUG-002 | IEEE 754 부동소수점 정밀도 오차 | 0.1은 2진수로 끝없이 반복되어 잘려서 저장됨 |
| BUG-003 | 문자 인코딩 불일치 | 저장할 때와 읽을 때 규칙(UTF-8, CP949)이 다름 |
| BUG-004 | 유니코드 정규화 형식 차이 | 같은 한글을 완성형(NFC)과 조합형(NFD)으로 저장 |
| BUG-005 | IME 입력 조합 상태 불일치 | 입력기와 프로그램이 기억하는 '조합 중' 글자가 어긋남 (추정) |

## 3. 페이지 구성

- **홈:** 레트로 CRT 모니터 화면의 시작 화면
- **오류 도감:** 사례를 검색하고 분류(숫자·문자·입력)별로 탐색
- **원인 해부실:** 증상 → 처리 과정(입력 → 처리 → 출력) → 원인 추적 기록 → 핵심 원리 → 해결 방법 → 출처
- **현상 실험실:** 원리를 실제 계산으로 확인
  - 2의 보수와 정수 오버플로, 2038년 시뮬레이터
  - 0.1 + 0.2 계산과 누적 오차 그래프
  - 글자를 바이트로 바꾸기 (UTF-8 / CP949)
  - 한글 쪼개 보기 (NFC / NFD)
  - 한글 조합 공식과 '완완성' 재현
  - 오류 검출: 패리티 비트와 XOR 체크섬
- **오류 비교실:** 두 사례의 공통점과 차이점, 원인 유형별 묶음

## 4. 설명의 근거

- 모든 사례에 공식 문서(Python, MDN, Unicode, W3C 등)와 보도 자료 출처를 연결했습니다.
- 원인 추적 기록의 각 단계에 **📘 문서로 확인** 또는 **🔎 추정**을 표시해, 확인된 사실과 추정을 구분했습니다.
- BUG-005의 재현 화면은 실제 녹화가 아니라, 직접 겪은 현상을 원리에 맞춰 다시 그린 것입니다.

## 5. 사용한 기술

- Python, Streamlit, GitHub, Streamlit Community Cloud
- 비트 연산(`&`, `|`, `^`, `~`, `<<`)과 2의 보수 해석
- 유니코드 한글 조합 공식 (`0xAC00 + (초성 × 21 + 중성) × 28 + 종성`)
- 문자 인코딩(`encode` / `decode`), 유니코드 정규화(`unicodedata`)
- 10진수 정밀 계산(`decimal`), SVG로 직접 그린 그래프

## 6. 실행 방법

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```
