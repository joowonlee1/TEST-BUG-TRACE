# BUG TRACE

### 조회수가 갑자기 음수가 되고, 0.1 + 0.2가 0.3이 아닌 이유는?

숫자를 정해진 비트에 저장하는 컴퓨터의 한계 때문에 생기는 오류(오버플로·언더플로·정밀도 오차)의 원인과 작동 원리를 분석하는 웹앱입니다.

🔗 웹앱 주소: https://bug-trace2-bqzgnugxyavjctzeovwxxn.streamlit.app/

## 1. 탐구 동기

비트 단위 연산 수업에서 정수를 2의 보수로 저장하는 방법을 배우며, 정해진 비트를 넘으면 음수가 되는 오버플로를 알게 되었습니다.
여기서 **"반대로 가장 작은 수보다 작아지면? 그리고 소수점이 있는 실수는 어떻게 저장되고, 어디서 한계가 생길까?"** 라는 의문이 생겼습니다.
여러 오류를 얕게 다루기보다 **정수와 실수, 두 사례를 깊게** 탐구하기로 했고, 2038년 문제와 '언더플로'의 두 가지 뜻까지 추적했습니다.

## 2. 탐구 사례

| 번호 | 사례 | 핵심 원리 |
|---|---|---|
| BUG-001 | 정수 오버플로 · 언더플로 | 최댓값·최솟값을 넘으면 2의 보수 규칙 때문에 반대쪽 끝으로 넘어감 (2038년 문제) |
| BUG-002 | 부동소수점 정밀도 오차 · 언더플로 | 가수 52비트에서 잘려 오차가 생기고, 0에 너무 가까우면 0이 되어 사라짐 (IEEE 754) |

> 정수에서는 최댓값과 최솟값이 경계이고, 부동소수점에서는 값의 절댓값이 너무 크거나 0에 너무 가까울 때 문제가 생깁니다.

## 3. 페이지 구성

- **홈:** 레트로 CRT 모니터 화면의 시작 화면
- **오류 도감:** 사례를 검색하고 분류(정수·실수)별로 탐색
- **원인 해부실:** 핵심 원리 → 용어 → 증상 → 처리 과정 → 원인 추적 기록 → 관련 영상(2038년) → 출처 → 해결 방법
- **현상 실험실:** 원리를 실제 계산으로 확인
  - ① 정수 오버플로·언더플로 (최댓값 + 1, 최솟값 − 1, 2의 보수 비트)
  - ② 2038년 시계 (부호 있는/없는 32비트, 64비트 비교)
  - ③ 0.1 + 0.2와 IEEE 754 64비트 보기, 누적 오차 그래프
  - ④ 실수 언더플로 (계속 반으로 나누면 정상 수 → 비정규 수 → 0)
- **오류 비교실:** 정수와 실수 항목별 비교, 오버플로·언더플로 2×2 정리
- **오류 검출:** 패리티 비트, XOR 체크섬, CRC 설명과 비트 뒤집기 실험
